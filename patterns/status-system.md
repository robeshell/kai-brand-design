# 通用状态系统

状态组件回答三件事：发生了什么、影响了什么、用户现在能做什么。它不是一组装饰插画，也不是每个业务各造一套进度组件。

## 状态模型

每个状态由四个维度决定：

- **范围**：整页、内容分区、单个对象、后台任务；
- **阶段**：准备、加载、运行、等待、暂停、完成、部分完成、失败、取消；
- **进度**：无进度、未知进度、确定进度、多阶段进度；
- **恢复性**：无需操作、可重试、需要修改输入、需要权限、不可恢复。

## 展示层级

| 范围 | 组件 | 使用方式 |
|---|---|---|
| 整页没有可展示内容 | Empty State / Blocking State | 居中但保持页面标题和导航可见 |
| 已有内容中的局部变化 | Inline Status / Progress Row | 放在受影响内容附近，不遮挡其他内容 |
| 用户刚完成的短操作 | 平台对应的短反馈 | 自动消失；仅在可撤销时带操作 |
| 需要持续关注的后台任务 | Persistent Task Status | 保持入口，完成后更新为结果 |
| 需要立即决定 | Dialog / Sheet | 仅用于必须处理的问题 |

## 空状态

| 原因 | 标题内容 | 操作 |
|---|---|---|
| 首次使用 | 说明这里会出现什么 | 提供创建或导入入口 |
| 数据确实为空 | 说明当前没有数据 | 有明确下一步时提供主操作 |
| 搜索无结果 | 回显查询词 | 修改查询、清除筛选 |
| 筛选无结果 | 说明哪些条件限制了结果 | 清除筛选 |
| 无权限 | 说明缺少的权限及用途 | 请求权限或打开系统设置 |

空状态不显示版本、统计、设计说明或与当前任务无关的引导。

## 加载与进度

- 首次加载且没有内容时使用页面级加载；
- 已有内容刷新时保留旧内容，使用局部进度；
- 总量已知才显示百分比或数量进度；
- 总量未知时显示当前阶段，不能伪造百分比；
- 超过短暂等待后才显示明显加载反馈，避免界面闪烁；
- 加载图形必须同时有可访问文字。

## 完成与错误

| 状态 | 信息 | 操作 |
|---|---|---|
| 成功 | 说明完成的具体结果 | 通常无需确认，可提供查看或撤销 |
| 部分完成 | 分别给出成功、跳过和失败 | 重试失败项、查看详情 |
| 可恢复错误 | 说明失败阶段和保留的数据 | 重试或修改输入 |
| 离线 | 说明哪些内容仍可使用 | 重新连接或继续离线 |
| 不可恢复错误 | 说明结果和下一条可行路径 | 返回、导出诊断或联系支持 |

连续失败应落成稳定状态，不能循环弹出短提示。错误不能只靠颜色、图标或错误代码表达。

## 组件解剖

状态展示按需要组合，禁止为了“完整”全部出现：

1. 状态图标或进度图形；
2. 具体标题；
3. 一句影响说明；
4. 当前阶段、数量或失败摘要；
5. 一个主要恢复操作；
6. 可选次操作或详情入口。

平台负责进度图形、通知、Dialog 和短反馈的原生呈现；品牌层统一语义色、图标语言、文字层级和信息顺序。
